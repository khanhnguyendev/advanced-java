Read `docs/superpowers/plans/diagram-draw-task.md` first, including ALL its "Lessons" sections: they all apply. This file only adds what is specific to the last 44 images (`docs/superpowers/plans/diagram-rest-manifest.json`; fields `id`, `upstream`, `license`, `batch`, `cls`, `note`, `hint`).

## Differences from the first run
- `license` comes from the manifest (`derived` for Eureka and the other unknown-provenance images; `third-party` for the Fowler/Richardson figures and the Sentinel-wiki figures). Write that value into the scene. The attribution text is generated from `source-credits.json`; you add nothing for it. Never write `original`.
- The docs that show these diagrams are served in Chinese only (en/vi translations are excluded or pending), so the zh labels are what readers see; en and vi labels are still required by the gate.
- Most Fowler/Richardson/Sentinel figures are English-origin: the reference locale is `en` (`status: "source"`, `source_lang: "en"`, zh and vi are translations with `from` = sha256 of the en file). The Eureka figures are Chinese-origin or English UI/code: see below.
- The owner asked for EVERYTHING to be redrawn, including screenshots and illustrations. Redraw them faithfully as schematic vector diagrams with the framework primitives. You may simplify decoration, never content: every text, every number, every structural relation must survive.

## Classes and how to draw them
1. **Sequence charts** (Eureka `*-sequence-chart.png`): participants are `box` nodes in one row at the top (full class names as literals, kept identical in all locales); each lifeline is a dashed vertical edge (`style: dashed`, `arrow: none`) from the participant's bottom edge down; each message is a horizontal solid edge with an arrowhead and its label as an edge label 4px above the line (method names are literals); a self-call is a small polyline loop to the right of the lifeline with its label to the right; activation bars (narrow rectangles on a lifeline) are blank-key narrow `box` nodes; fragment frames (`loop`, `alt`) are `group` nodes with `border: solid` and a short label top-left. Keep the vertical order of the messages exactly. The chart titles (zh) are texts at the top.
2. **IDE code screenshots** (Eureka `eureka-server-*` and `registry-structure`): the code is not translatable. Draw the panel as a `group` (`border: solid`, blank key) with one free text per code line inside it; each line is a literal (the whole line) so it is identical in all locales and rendered in mono; keep the original indentation as leading spaces inside the literal. Red highlight boxes of the screenshot become nested solid `group` nodes around the highlighted lines (blank key) with `accent`-style emphasis only if upstream's highlight is red (the gate has no group role: use a solid group border; if you cannot make the emphasis visible, say so). Method/line-number gutters and the IDE chrome (tabs, toolbar) are dropped; the file/tab name, if visible, is kept as a text above the panel. Keep line breaks; make the canvas as wide as needed so no line wraps (long lines are not wrapped inside literals).
3. **UI screenshots** (Eureka homepage, instance list, Sentinel dashboard): panel `group` with header texts, table rows as texts aligned in columns (use free texts with explicit x positions; row separators as plain edges), buttons/tabs as small `box` nodes, status colours as `accent` where the screenshot shows red/green emphasis. UI strings are literals identical in all locales (they are product UI text); explanatory words you add (`_title`, `_desc`) are translated.
4. **Charts** (Sentinel Slow-Start, timelines): axes and gridlines as plain edges, series as polylines (`style: accent` for the highlighted series), tick labels and values as texts (literals when numeric), legend as text.
5. **Illustrations** (`bulkhead-partition.jpg` ship, `BRP.jpg` funnel): draw a simplified schematic with `box`/`group`/polyline edges that conveys the same idea (a hull divided into watertight compartments; a funnel/bottleneck with items flowing through). No decorative detail. Text only where the original has text. Describe the schematic in `_desc` so it is accessible.
6. **Architecture/flow diagrams** (the Fowler/Richardson figures: hexagonal architecture, scale cube, event sourcing ...): as in the first run. Hexagons: `box`/`round` nodes approximating hexagon cells are acceptable; keep the adjacency.

Report format as before (files, label instances counted, gate output, runs and iterations, new glossary entries, uncertainties, which PNGs you actually read).
